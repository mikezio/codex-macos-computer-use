# Asset placeholders and final art direction

This folder intentionally uses working placeholder assets so the plugin install surface is complete now, while the final visual pass can still be done deliberately.

## Why placeholders are here

The repo needs valid icon and logo paths today. What it does not need is rushed art that looks unfinished or inconsistent. These placeholders keep the project installable and make the remaining design work explicit.

## Files in this folder

- `icon-placeholder.svg`
  - current stand-in for the plugin icon
- `logo-placeholder.svg`
  - current stand-in for the plugin logo
- `screenshot-placeholder.svg`
  - stand-in preview image for repo or catalog use

## Final icon brief

Create a square 1024 by 1024 plugin icon for a local macOS desktop automation tool called macOS Computer Use.

The icon should communicate:

- controlled desktop interaction
- reliable local tooling
- precision and guardrails
- premium developer product quality

Composition:

- dark background
- elevated rounded square container
- simplified floating window or desktop panel
- cursor, crosshair, or target motif suggesting precise control

Style:

- premium product icon
- clean vector look
- subtle depth and lighting
- crisp geometry
- readable at 32 by 32 and still strong when large
- no text

Color direction:

- deep midnight navy or near black base
- teal or green accent for trust and action
- muted cool blue secondary accent
- soft neutral panels for UI surfaces

Avoid:

- cheesy hacker visuals
- skulls, locks, shields, or warning triangles
- terminal code rain
- fake glossy app store effects
- copied OpenAI brand marks

## Final wide logo brief

Create a wide hero logo image for the repository and plugin listing.

The image should feel like a serious developer tool banner for local desktop control on macOS.

Composition:

- premium dark background with subtle depth
- central product moment such as a simplified macOS style window or panel
- visible cursor or targeting element indicating precision
- restrained environmental layer hinting at desktop workflow

Tone:

- calm
- precise
- trustworthy
- premium developer tooling
- not noisy
- not playful consumer branding

Avoid:

- bright rainbow gradients
- cyberpunk hacker clichés
- stock illustration people
- fake holograms
- copied Codex or OpenAI symbols

## Final preview screenshot brief

Create a polished preview image for a repo page, release page, or plugin listing.

Format:

- 1600 by 900 or similar wide landscape frame
- dark mode friendly
- crisp enough for GitHub README or catalog use

Scene to depict:

- a main app window representing a controlled desktop session
- a smaller side panel or terminal style panel showing structured action output
- a visible targeting or cursor element indicating precise interaction
- subtle cues of screenshot first verification such as snapshot thumbnails, before and after states, or a focused verification panel

Product story:

This is not generic automation. It is careful, local, approval aware desktop control for developers.

The scene should imply:

- observe the state
- take one action
- verify the result
- continue safely

Avoid:

- anime or illustration styles
- fake hacker rooms
- noisy glowing overlays everywhere
- exaggerated futuristic nonsense
- overly literal warning icons

## Acceptance bar

Someone seeing the final asset set should immediately think this looks like a thoughtful local desktop operator tool for Codex on macOS.
